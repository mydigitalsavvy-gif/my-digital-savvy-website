| Item | Class | Explanation |
|---|---|---|
| `/nargis/` (all fields) | SPECIAL_CASE | Served byte-identical from WordPress (passthrough). The live page has its own title, description and OG tags, no canonical and no robots tag; Next.js output is the same bytes. |
| `/thank-you/` canonical, robots, OG description | SPECIAL_CASE | The live page's custom template prints no canonical or robots tag. Next.js applies Yoast's stored values: **noindex, follow** and a self canonical. The page stays non-indexable and out of the sitemap. |
| Blog posts, author archive, thank-you — H1 | SPECIAL_CASE | Live HTML has **no H1** on these templates. Next.js renders the post / archive title as the H1 (gain, not loss). In-content H1s are demoted to H2 so each page has exactly one H1. |
| Homepage — H1 | **MISMATCH** | Live: "MY DIGITAL SAVVY - Best Digital Marketing Agency in Nagpur" (plus "My Digital Savvy"). Next.js (frozen design): "Marketing that pays for itself in hospitality." — and the rotor's decorative duplicate makes the DOM text "…hospitality.hospitality.". Title, description and canonical are unchanged. **Human decision** (design is frozen). |
| `twitter:title`, `twitter:description`, `twitter:image` | equivalent | Yoast prints only `twitter:card` (plus label/data pairs, which Next.js now reproduces) and lets X fall back to Open Graph. Next.js always auto-fills these three tags from Open Graph with **identical values**; there is no opt-out. Previews are identical. Not a ranking signal. |
